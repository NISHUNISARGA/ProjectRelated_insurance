### T051. "Why does the handler use `$lt` with dateTo + 1 day instead of `$lte` dateTo?"

**Strong answer:** The Oracle SQL is `TRUNC(CREATED_DATE) BETWEEN from AND to`: whole days, both ends included. In Mongo `CREATED_DATE` is a full timestamp. `toDate` turns "2026-01-31" into 2026-01-31 00:00 UTC. With `$lte` that midnight, almost all of the last day is lost, and from = to returns only rows at exactly midnight. So the fix is a half-open range: `CREATED_DATE >= from 00:00` and `< (to + 1 day) 00:00`. This is the same as `TRUNC(x) <= to`. It also keeps `CREATED_DATE` as a bare field so an index can be used; wrapping it in `$dateTrunc` would block the index (comment in the handler, lines ~37-41).

**Weak answer:** "It is a bug fix for dates." Or "`$lt` is faster."

**Red flags:** Cannot explain TRUNC. Says the time part is irrelevant.

**Follow-up questions:**

### T057. "Oracle sorts by NAME_EXT. Does your Mongo sort give the same order?"

**Strong answer:** Not for nulls. Oracle `ORDER BY x ASC` puts NULLs last. MongoDB ascending puts null and missing first. Customers with no partner match (or null `NAME_EXT`) therefore appear at the top in Mongo and take the first `rowNumber` values. Binary order is the same for plain ASCII in both systems (inferred).

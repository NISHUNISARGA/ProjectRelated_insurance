### T172. "Why Strategy pattern with bean names equal to report paths?"

**Strong answer:** The old controller used a ~50-case `switch(reportName)`. New reports must implement `ReportStrategy` and register `@Service("<report path>")`; Spring injects `Map<String, ReportStrategy>`; the controller does a map lookup first and falls back to the switch. It keeps old routes intact and lets new reports be added without touching the controller. The bean name equals the Jasper path, so the existing callers need no change. Trade-offs: bean names are strings with slashes (typos give an empty 200), no compile-time check, `PlineReportNames` derives main names from the string, and the name is the only versioning.

**Weak answer:** "It is a Spring feature."

**Red flags:** Cannot explain the fallback.

**Follow-up questions:**

- Risk of two beans with the same key? (Startup failure or override depending on config; the merge avoided it by disabling.)
